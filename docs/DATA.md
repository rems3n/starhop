# Catalog data (public/data)

Everything in `public/data/` except `images.json` is generated by the pipeline in `scripts/data/`.
Shapes are defined in the "Catalog data" section of `src/types.ts`. All positions are J2000, in degrees
(RA 0–360). Checks live in `tests/data.test.ts`.

## Rebuild

```
npm run data                          # = tsx scripts/data/build-all.ts
npx vitest run tests/data.test.ts
```

Raw sources are downloaded once into `scripts/data/raw/` (gitignored) and reused. Delete a file there to
fetch it again. `raw/manifest.json` records URL, download time and SHA-256 of each raw file;
`raw/build-report.txt` is the full build log (counts, every exception listed below). With a warm cache the
build is byte-identical: `meta.json`'s `builtAt` is the download time of the newest raw file, not the
time the script ran. Wikipedia requests are spaced 1.5 s apart and retried on HTTP 429.

| `../deep/dsos.json` | 721 kB / 222 kB | 11,202 further NGC/IC/addendum objects |

**stars.json** — `Star[]`, brightest first (ties by id). `id` is the HYG id. Unknown fields are left
out. Rounding: ra/dec 5 decimals, mag 2, bv 3, absMag 2, distLy 3 significant figures.

**stars-faint.json** — `FaintStars`: four parallel arrays (`ra`, `dec` 4 decimals; `mag`, `bv` 2
decimals), brightest first. `bv` is 0.6 where HYG has no colour. For drawing only; no ids.

**constellations.json** — `Constellation[88]` in alphabetical order of Latin name, with stick-figure
`lines`, `figureStars`, `mainStars`, densified `boundary`, label anchor, IAU area, season, hemisphere,
zodiac flag.

**dsos.json** — `Dso[]`, brightest first, objects without a magnitude last (ties: Messier, then
Caldwell, then id).

**milkyway.json** — `MilkyWay`: `levels[0]` is level 1, the outermost and faintest contour; level 5 is
the brightest core. Each polygon is one closed outline (the closing point is not repeated).

**meta.json** — `{ builtAt, counts, files, sources[] }`; each source has name, url, licence, version
and what it was used for.

**public/deep/** (the "Fainter stars and objects when zoomed in" layer; formats and the shared codec in
`src/sky/deepcore.ts`, HEALPix maths in `src/sky/healpix.ts`):

- `stars/index.json` — `{ version, idBase, bands: [{ min, max, order, counts[] }], total, source }`. Band 0 is
  7.6 < mag ≤ 9.5 at HEALPix order 2 (nside 4, 192 tiles); band 1 is 9.5 < mag ≤ 11 at order 3 (nside 8, 768 tiles).
  `counts[p]` is the number of stars in nested pixel `p` (no file when 0; none are empty).
- `stars/<order>/<pixel>.bin` — `u32 count · f32 R · u16 ξ[n] · u16 η[n] · u8 mag[n] · i8 bv[n]`, little-endian, 8 + 6
  bytes per star. ξ/η are gnomonic (tangent-plane) offsets from the pixel centre quantised over [−R, R] (error < 1″;
  tested); mag = byte/20; B−V = byte/50, −128 = unknown. Brightest first, so a limiting magnitude is a draw count.
- `stars/<order>/<pixel>.json.gz` — identity of the same stars in the same order: `{ d: designation[], m: mag×100[],
  l: distance in ly (0 = none)[], s: spectral type[] }`, gzip-compressed on disk (the client checks the gzip magic
  bytes, so it works whether or not a server adds `Content-Encoding`). Fetched only when a deep star is clicked.
- `dsos.json` — `{ version, cols, types, rows }`, one row per object: `[id, ra, dec, typeCode, mag|null, majAx|null,
  minAx|null, con, name, hubbleType, aka]` (`aka` joined with " · "). `deepDsosFromFile()` in `src/data/catalog.ts`
  turns rows into ordinary `Dso` objects. Brightest first, no magnitude last.

## Rules: stars

- The Sun (HYG id 0) is excluded.
- `distLy` = parsecs × 3.26156. HYG uses ≥ 100000 pc for "unknown"; those stars (206) have no `distLy`
  and no `absMag`.
- `name` is the HYG `proper` column (IAU names; HYG 4.1 also names some companions "… B").
- `bayer`: HYG writes `Alp`, `Pi-3` (column `bayer`) and `21Alp And`, `Kap1Scl`, `1Pi 3Ori` (column
  `bf`). Both forms are parsed to unicode Greek plus an optional index (`α`, `π3`). All 1,517 values
  parsed; none were left over.
- `desig`: `α Ori` if Bayer, else `58 Ori` if Flamsteed, else `HR n`, `HD n`, `HIP n`. 24 faint
  companions have none of these and keep their Gliese name (for example `Gl 702B`).
- `con`: HYG's value. No star needed fixing (only the Sun was blank). The fallback order, if ever
  needed, is the constellation in the designation, then `Constellation()` from astronomy-engine.
  One star's HYG constellation differs from the boundary lookup; HYG's is kept so the designation
  stays consistent.

## Rules: constellations

- `name`, `genitive`: d3-celestial. Its two Serpens entries (Caput, Cauda) become one `Ser` named
  "Serpens" with two boundary polygons and both line sets.
- `english`: authored table in `scripts/data/constellation-table.ts` (d3-celestial's English field is
  a bare noun, not the "the Hunter" form).
- `areaSqDeg`: authored table of official IAU areas. The build fails unless all 88 match Wikipedia's
  table and each agrees within 1 % with the area of our own boundary polygon.
- `ra`/`dec` label anchor: d3-celestial's label position. For Serpens it is the head (Serpens Caput).
- `season`: anchor dec > +60 → north-circumpolar; < −45 → far-south; otherwise by anchor RA:
  3h–9h winter, 9h–15h spring, 15h–21h summer, 21h–3h autumn. `hemisphere`: N if anchor dec ≥ 0.
- `zodiac`: the twelve traditional ones (not Ophiuchus).
- `lines`: longitudes −180..180 converted to RA. Each vertex is snapped to a star in `stars.json`: the
  brightest star within 0.1°, otherwise the nearest within 0.7°. The line is drawn through the
  snapped star's position. Every vertex snapped within 0.1°; none failed.
- `figureStars`: the snapped stars, unique, brightest first.
- `mainStars` (scores "circle the constellation" questions): figure stars that belong to the
  constellation, with mag ≤ 4.6. If that gives fewer than 4, the 4 brightest of them (or all, if
  fewer). At most the 14 brightest. Two traditional shared stars also count: Alpheratz for Pegasus and
  Elnath for Auriga.
- `brightest`: brightest star whose `con` is this constellation.
- `boundary`: IAU boundaries run along lines of constant RA or Dec in the B1875 frame. Each edge is
  rotated to B1875, subdivided linearly there (short way round in RA) so no step is longer than 1°,
  and rotated back. Points are rounded to 4 decimals; the closing point is not repeated.

Exceptions:

- **Canis Minor and Canes Venatici have 2 main stars.** Their figures are a single line between two
  stars. Every other constellation has 3 to 14.
- **12 figure stars belong to a neighbour** (98 % of all figure stars are in their own
  constellation): Aur–Elnath (Tau), Peg–Alpheratz (And), Car–γ2 Vel, Car–Alsephina (Vel), Car–ν Pup,
  Pup–γ2 Vel, Pyx–Naos (Pup), Eri–π Cet, and Ser–Sabik, Yed Prior, ν Oph, τ Oph (d3-celestial draws
  the serpent through Ophiuchus). Serpens is the lowest at 10 of 14 own stars.
- **6 points removed from d3-celestial's boundaries.** They sat up to 0.4° off the +88° parallel
  between Cepheus and Ursa Minor; the arc is rebuilt from its end points.

## Rules: deep-sky objects

Included (597):

1. All 110 Messier objects. M40 is the double star Winnecke 4, M45 the Pleiades (Mel 22), M24 the
   star cloud IC 4715, M73 an asterism (NGC 6994). **M102 is taken to be NGC 5866**; the
   identification is disputed and OpenNGC itself treats M102 as a duplicate of M101.
2. All 109 Caldwell objects, mapped through Wikipedia's table. C9 (Cave Nebula), C14 (Double
   Cluster), C41 (Hyades) and C99 (Coalsack) have no single NGC/IC number and come from OpenNGC's
   addendum.
3. 366 other OpenNGC objects with V magnitude (B if there is no V) ≤ 10.0. Skipped: duplicate and
   non-existent entries, single stars, double stars, novae, "other" entries (17), and `NED` sub-entries.
4. 12 famous objects that fail rule 3: LMC, SMC, Horsehead (B33), IC 434, NGC 869, NGC 884,
   California, IC 1805, IC 1848, Flame, Coathanger, Coma Star Cluster (Mel 111).

Fields:

- `id`: `M42`; else `NGC869` / `IC434`; else `LMC`, `SMC`, `Mel25`, `Cr399`, `B33`, `C9`, `C14`,
  `C99`, or the addendum name without padding (`H5`, `ESO356-4`).
- `aka`: other designations in display form (`NGC 1976`). The Caldwell number is in `caldwell`.
- C14 is one entry (the Double Cluster, `aka` NGC 869 and NGC 884); NGC 869 and NGC 884 are also
  separate entries without a Caldwell number. C50 keeps the id `NGC2244` although OpenNGC stores it
  under NGC 2239.
- `name`: Messier → the title of the object's Wikipedia article when it has a named one ("Orion
  Nebula"); Caldwell → the first name in Wikipedia's list; otherwise OpenNGC's first common name.
  A short override table in `build-dsos.ts` fixes about 20 (for example "47 Tucanae", "Jewel Box").
  IC 434 has no name (OpenNGC's "Orion B" is the whole cloud). When a non-Messier, non-Caldwell
  entry has the same name as a Messier/Caldwell object, its name is dropped (IC 4703 "Eagle Nebula",
  NGC 2238 "Rosette Nebula"). 116 objects have a name.
- `type`, from the OpenNGC code: G, GPair, GTrpl, GGroup → galaxy; OCl → open-cluster; GCl →
  globular-cluster; Cl+N → cluster-with-nebula; PN → planetary-nebula; HII, EmN → emission-nebula;
  RfN → reflection-nebula; SNR → supernova-remnant; DrkN → dark-nebula; Neb → nebula; \*Ass →
  asterism; \*\* → double-star. For Messier/Caldwell objects whose code is vague (Neb, \*Ass, Other),
  the type in Wikipedia's list is used when it is specific: M8, M16, M17, M20, NGC 7023 →
  cluster-with-nebula; M24 → star-cloud; M73 → asterism; C14 → open-cluster.
- `typeDetail`: OpenNGC's Hubble type, galaxies only.
- `mag`: V, else B (40 objects, mostly nebulae), else the value in Wikipedia's list (24
  Messier/Caldwell objects, including M22, M35 and the Jewel Box).
- `sizeArcmin`: `[MajAx, MinAx]`; the minor axis repeats the major when OpenNGC has only one.
- `con`: OpenNGC's, with `Se1`/`Se2` → `Ser`.
- `distLy`: only for Messier and Caldwell objects, from the Wikipedia list tables, which are in
  thousands of light-years (× 1000, rounded to a whole light-year). Where the table gives a range, the
  table's own central value is used. Checked: M31 2,540,000; M42 1,344; M13 22,200; M45 425.
- `equip`, assuming a dark sky: mag ≤ 4.6 naked-eye; ≤ 7.6 binoculars; ≤ 10 small-telescope; fainter
  or no magnitude → telescope. Always naked-eye: LMC, SMC, Hyades, Coalsack, Coma Star Cluster.

Known gaps:

- **No distance for the 378 objects that are neither Messier nor Caldwell**, including the LMC and SMC.
- **No magnitude** for NGC 6729 (C68), Coalsack, Horsehead, Flame Nebula, Coma Star Cluster.
- **`equip` is too optimistic for large faint nebulae**, because one magnitude spread over a big
  area says little about visibility. Examples: North America Nebula and IC 4592 come out naked-eye;
  California, both Veil halves, Crescent and Rosette (NGC 2238) come out binoculars.
- C49: Wikipedia says NGC 2237, OpenNGC tags NGC 2238. We follow Wikipedia; both entries exist.
- Seven \*Ass entries are typed `asterism`; some are loose star groups in the LMC.

## Rules: deep stars (AT-HYG)

AT-HYG v4.0's magnitude-11 subset has 875,292 rows (Tycho-2 positions and VT magnitudes for most, V for Hipparcos and
Gliese stars; Gaia DR3 distances for ~99 %). RA is in hours, distance in parsecs (as in HYG). 47 rows contain quoted
fields and are parsed quote-aware; the rest are split on commas.

- Skipped: the Sun; 2,047 stars fainter than 11 (the subset keeps all stars within 100 ly regardless of magnitude).
- **Deduplicated against what we already ship** (every HYG v4.1 star with mag ≤ 7.6, i.e. `stars.json` +
  `stars-faint.json`): same HIP number (28,414), else same HD number (152), else a shipped star within 2″ whose
  magnitude differs by ≤ 1.0 (178). 1,335 of the stars kept lie within 10″ of a shipped star; these are close pairs
  (a different magnitude) or, rarely, a duplicate the rules did not catch.
- **1,372 AT-HYG stars at mag ≤ 7.6 have no HYG match and are left out** (Tycho stars whose VT is a little brighter than
  HYG's limit, e.g. HD 224862 at 7.23): adding them only to the zoomed-in tiles would make them pop in when zooming.
- Kept: 843,128 stars, 7.6 < mag ≤ 11.
- `d` (designation): IAU proper name, else `HD n`, else `HIP n`, else `TYC a-b-c`, else `Gaia DR3 n`.
  `l`: distance × 3.26156 to 3 significant figures, only when `dist_src` is a Gaia source and 0 < dist < 100,000 pc.
  `s`: AT-HYG's `spect` when present. B−V is AT-HYG's `ci`.
- **Why these tile sizes.** 171,216 stars in band 0 over 192 tiles (mean 892, median 741, max 2,414) and 671,912 in
  band 1 over 768 tiles (mean 875, median 689, max 4,187). That is ~5 kB per render file on average (≤ 25 kB), big
  enough that a zoomed view needs only a handful of requests (a 4° view: 9–11 files, 24–118 kB) and small enough that
  little is fetched off screen. The brighter band is needed from ~17° fields inwards (Bortle 6), where coarser tiles
  (~15° across) fit the view; the faint band only below ~7°, where ~7° tiles fit. A single order-4 split (the lead's
  first suggestion, ~275 stars per tile) would have meant up to 4× as many requests for the same view.
- Deep star ids (`star:<id>`) are `10,000,000 + band·2²⁶ + pixel·2¹⁴ + index` (`deepStarId`), so they never collide
  with HYG ids and are stable for one build of the tiles. The build fails if a tile ever holds ≥ 16,384 stars.

## Rules: deep-sky objects beyond dsos.json

Every OpenNGC `NGC.csv` + `addendum.csv` row except: Dup/NonEx (662), stars, double stars, novae and "Other" (1,213),
`NED` sub-entries (361), and objects already in `dsos.json` by id or any NGC/IC cross-identifier (596). Result: 11,202
objects (10,307 galaxies, 373 open clusters, 134 globulars, 103 planetary nebulae, …), 10,534 with a magnitude, 45 with
a common name. Fields follow the `dsos.json` rules (type map, V else B magnitude, `Se1/Se2` → `Ser`, constellation from
the position when OpenNGC's is not one of the 88); no Wikipedia data, no distances. `equip` is computed in the client
by the same magnitude rule (`equipForMag`): mostly `telescope`.

## Rules: Milky Way

d3-celestial `mw.json` has features `ol1` (outermost) to `ol5` (innermost), each one multipolygon
whose rings are contour outlines. Every ring becomes one polygon. Points are thinned with
Douglas–Peucker at 0.06° (30,474 → 7,388 points), rounded to 2 decimals; one ring with fewer than 4
points was dropped. Within a level, polygons are ordered by point count.

For whoever renders it: the rings are **not** independent filled shapes. In level 1 the two largest
rings are the northern and southern edges of the band, each running all the way round the sky; the
remaining rings in any level may be islands or holes. Filling each ring on its own will be wrong for
level 1. Filling all rings of a level together with an even-odd rule gives the intended area. The
`MilkyWay` type has no way to mark holes.
