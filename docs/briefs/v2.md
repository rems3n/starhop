# Starhop v2 — structure, library, navigation (shared brief for all v2 engineers)

## The client's request (verbatim intent)

Make Starhop a general-purpose night-sky course and reference that works for **anyone, anywhere** — not a
Brooklyn-specific study plan — with a clear curriculum, browsable reference libraries, structured star-hopping,
filters on every embedded sky map, all myths in one place, and navigation where each top-level section is what
it says.

## Target information architecture

| Section (nav label) | Route | Contents |
| --- | --- | --- |
| **Sky** | `/sky` | The full sky map (Explore). `?target=` and `?t=` deep links as before. |
| **Tonight** | `/tonight`, `/tonight/month[/:m]`, `/tonight/calendar`, `/tonight/events` | What's up tonight from your location; monthly guides; visibility calendar; year-ahead events. |
| **Learn** | `/learn`, `/learn/module/:id`, `/learn/lesson/:id` | Only the course: 8 numbered modules (`src/content/course.json`), each with purpose, objectives, lessons/constellations, progress and a closing practice quiz. |
| **Library** | `/library`, `/library/constellations`, `/library/constellation/:id`, `/library/myths`, `/library/myth/:storyId`, `/library/starhops`, `/library/starhop/:id`, `/library/asterisms`, `/library/asterism/:id`, `/library/stars`, `/library/objects`, `/library/object/:ref`, `/library/planets` | Reference "database" views with search, filters, sort; detail pages. |
| **Practice** | `/practice`, `/practice/{find,name,object,story,knowledge,visibility,starhop}`, `/practice/module/:id`, `/practice/lesson/:id`, `/practice/review`, `/practice/progress` | Quizzes, spaced-repetition review, progress dashboard. |

Phone: a 5-item bottom bar (Sky, Tonight, Learn, Library, Practice). Location and night-vision move to a
settings menu (gear/place button in the header; on phones in the top-right of the screen).

**Old routes must redirect** (keep query strings): `/explore` → `/sky`; `/learn/tonight` → `/tonight`;
`/learn/month/:m` → `/tonight/month/:m`; `/learn/calendar` → `/tonight/calendar`; `/learn/events` → `/tonight/events`;
`/learn/constellations` → `/library/constellations`; `/learn/constellation/:id` → `/library/constellation/:id`;
`/learn/objects` → `/library/objects`; `/learn/object/:ref` → `/library/object/:ref`; `/learn/signposts` →
`/library/asterisms`; `/learn/signpost/:id` → `/library/asterism/:id`; `/learn/lessons` → `/learn`;
`/learn/unit/:id` → `/learn`; `/quiz/*` → `/practice/*` (`/quiz/unit/:id` → `/practice`); `/progress` → `/practice/progress`.

**All links use `routes` from `src/lib/routes.ts`.** Never hand-write a path string.

## Location-neutral rules (everyone)

- No hard-coded "Brooklyn", "New York", "40°N", or northern-only assumptions in UI strings or logic. Use the
  learner's `useSettings().observer` (name, lat, lon, tz) and compute.
- Seasons are named by months ("December–February evenings"), or as "northern winter / southern summer" when a
  season word is needed. Use the hemisphere of the observer to decide.
- First run: until `useSettings().locationChosen` is true, show a friendly location prompt (search cities, use
  device location, or keep the default) before location-dependent content. The default observer stays as a
  fallback but is never assumed to be the learner's home.

## Shared contracts (do not change; request changes in `docs/requests/v2-<area>.md`)

- `src/lib/routes.ts` — route helpers.
- `src/content/course.json` + `courseModuleSchema` — the 8 modules. `src/content/course.ts` — `resolveCourse(observer, catalog)`
  returns modules with location-dependent `groups` (anchors/seasons/beyond) and `starhopIds`.
- `src/content/starhops.json` + `starhopSchema` — the star-hop library (`starhops`, `starhopById` from `@/content`).
- `src/components/sky-embed` — `<SkyEmbed options onReady controls="full|limited|none" allowedLayers openTarget onUserChange>`.
  Every embedded sky view (everything except the full Sky page) uses it instead of `<SkyView>`.
- `useSettings` gains `locationChosen`; `setObserver` sets it to true.
